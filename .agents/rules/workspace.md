# 作用域与清理

适用于本仓库内的一切操作者：AI 助手、维护脚本、人工。

## 一、作用域封闭：只动本项目文件夹

**根目录 = 本仓库（`astrbot-plugin-karin-ctl/`），一切创建、读取、编辑、删除、移动、执行都必须落在内部。** 禁止写入仓库外的路径（AstrBot 源码目录、`data/` 下其它目录、其它插件），禁止删除或移动仓库外路径，禁止改宿主环境（全局 `pip install`、AstrBot 配置、系统环境变量）。

只读例外：排障时读同一台机器上的 AstrBot 日志，仅限读。临时例外：系统临时目录用于一次性验证，用完立即删。

判断标准：**一条命令执行完，仓库之外应当没有任何变化。** 部署（放进 `data/plugins/`、重启、面板填配置）属于使用者的动作，助手不得执行，必须先得到明确同意。

## 二、构建与提交：等指令

以下动作不得自作主张，必须等用户明确要求：提交（`git init`/`add`/`commit`/`push`/打 tag）、改版本号（`metadata.yaml` 的 `version`，同步 `pack.mjs` 的 `ZIP_NAME` 与 README/INSTALL 的包名）、发布到市场、部署与重启。改完代码后只报告「改了什么、验证结果如何」。

## 三、产物清理：一次性即弃

`py_compile` 产生的 `__pycache__/` 必须删掉；临时脚本用完即删；清理只针对本次创建的对象。自检（应无输出）：

```bash
ls -d __pycache__ 2>/dev/null
find . -maxdepth 2 \( -name '_*' -o -name '*.pyc' -o -name '*.tmp' \) -print
```

## 为什么定这么死

这个插件能在用户 QQ 群里发消息、能让 Karin 执行任意已注册指令。它出问题会是**用户看得见的社交后果**，不是一条日志。所以边界写在文档里，而不是靠运行时自觉。
